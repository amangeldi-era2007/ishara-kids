# Добавление официальной карточки

Карточки в `src/data/atlas.ts` представляют письменные понятия, а не транскрипции жестов. Учебный ориентир: [презентация «е-Ымдау» Центром](https://special-edu.kz/news/6/single/1529) и размещённые там [методические рекомендации](https://special-edu.kz/beta/upload/files/2022/MP%20Video%20dictionary%20JY.pdf). Ссылка на источник не заменяет разрешение на распространение файла.

1. Добавьте объект в JSON-массив `src/data/reviewed-entries.json`. Используйте поля `signSchema` из `src/data/atlas.ts`. Совпадающий `id` заменяет демо-запись и сохраняет связь с уроком. Для черновика используйте `pending` и оставьте поля медиа пустыми. В `public` кладите **только** файлы, разрешённые к публичному скачиванию: GitHub Pages отдаёт их даже без ссылки в интерфейсе.
2. После сверки понятия и контекста специалистом запишите `reviewed_by`, точное `source_name`, `source_url`, основание публикации в `license`, дату и вариант в `notes`. `title_kz` и `description_kz` — письменный казахский, `title_ru` и `description_ru` — русский.
3. Разместите разрешённое MP4/WebM и субтитры VTT в `public/content/videos/`, подсказку в `public/content/images/`, обложку в `public/content/thumbnails/`. Имена файлов — латиница, цифры, `_` и `-`. В записи используйте пути от `/content/`, без `public` и без префикса GitHub Pages. Для `captions` укажите `caption_language` (`ru` или `kk`).
4. После проверки воспроизведения и текста установите `verification_status: 'verified'`. Урок и словарь используют один компонент. Ошибка загрузки ведёт к текстовой подсказке; до проверки видео не рендерится. Не подтверждайте карточку только потому, что файл существует.
5. Запустите `npm test` и `npm run build`. Проверьте тот же материал в словаре и на вводном экране урока. Для нового урока добавьте запись в маршрут с явной ссылкой на идентификатор карточки.

Пример одной записи для массива импорта (черновик, без заявления об официальном происхождении):

```json
{
  "id": "book", "title_kz": "Кітап", "title_ru": "Книга",
  "category": "school", "word_or_concept": "book", "icon": "📘",
  "description_kz": "Оны оқу үшін ашады.", "description_ru": "Её открывают, чтобы читать.",
  "image_hint": "/content/images/book.svg", "video_url": null, "thumbnail": null,
  "source_name": null, "source_url": null, "verification_status": "pending",
  "reviewed_by": null, "notes": "", "license": null, "captions": null
}
```

## Включение автоматической оценки

`src/data/practice-templates.json` хранит координаты **разрешённых эталонов**, а не кадры детей. Для каждой статической буквы нужны отдельная проверенная карточка и класс с тем же `id`. Каждый образец хранит 21 точку `worldLandmarks` с начала индексации MediaPipe, `handedness` (`Left`/`Right`) и берётся из незеркального исходного кадра. Нужны как минимум три пригодных образца для каждой сравниваемой руки в двух или более классах.

Задайте `maxDistance` и `minMargin` на отдельной группе исполнителей. В поле `validation` запишите происхождение, разбиение, положительные и отрицательные примеры и измеренные ошибки. Для этого сравнения используются средние квадраты 3D-расстояний по трём ближайшим образцам; пороги для пиксельных координат и других моделей не переносятся. Непроверенные и динамические классы не включайте.
